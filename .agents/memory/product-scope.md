SecondSignal is a campus resource-sharing community, not only a sales marketplace. The user now requests upgrading the existing demo in phases into a real student social marketplace using Supabase authentication, PostgreSQL, storage and realtime where appropriate. Preserve the existing app rather than rebuilding it.

**Why:** The latest full-stack brief supersedes the original frontend-only scope. Real accounts, posts and private messages must persist across sessions. Payments remain out of scope; matching must use actual listings and be labelled basic search without an AI provider.

**How to apply:** Retain the demo banner until corresponding backend functionality is implemented and tested; exclude sample data from the production experience. Follow the user's phases: inspect, backend/auth/security, composer, database-connected views, messaging/requests/notifications, matching/testing. Report completion and configuration needs after each phase. Preserve one visual identity on all routes: warm ivory #F8F7F2, forest green #174C3C, sage #A8BDAA, charcoal #252B27, muted grey #777D77, white surfaces and beige #E9E7DF borders, with Manrope and DM Sans. Both participants must confirm handover before completion; AI matching never completes transactions.
